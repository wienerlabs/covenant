# Covenant — Mainnet Deployment Runbook

Covenant ships **devnet-locked by default**. Mainnet is activated entirely by
environment variables — no code change is required at deploy time. This runbook
is the full go-live procedure for moving the protocol + app to Solana
mainnet-beta with **real USDC**.

> ⚠️ This moves real money. Every step below is the operator's responsibility.
> Do a full dry-run on a preview deployment first.

---

## 0. Pre-mainnet blockers (do these FIRST)

These are hard gates. Do not deploy to mainnet until each is cleared.

- [ ] **Rebuild + redeploy the program with the merged security fixes.** The
      on-chain fixes from the security audit (init_config upgrade-authority gating,
      escrow-PDA pinning, buy_claim self-dealing guard, finalize rent) only take
      effect in a **freshly built + deployed** program. A mainnet deploy must be
      built from `main` at or after those merges.
- [ ] **Rotate any leaked program/deploy keypairs.** Confirm no deploy or program
      keypair is present in git history. Generate fresh keys for mainnet.
- [ ] **External security audit.** The internal audit closed the known findings,
      but a real-money launch should have an independent audit + a monitoring tail.
- [ ] **Activate mutating-endpoint auth.** Set `SESSION_SECRET` (>=16 random chars)
      and verify wallet-session login works (see `.env.example`, C-091).
- [ ] **Decide the admin/upgrade authority.** Prefer a **Squads multisig** or a
      hardware wallet — not a hot key. This identity gates `init_config` and all
      future program upgrades.

## 1. Build the mainnet program

The program's `declare_id!` and `Anchor.toml` must carry the **mainnet** program
ID. Generate a fresh keypair for mainnet (never reuse the devnet program key).

```bash
# 1. Fresh mainnet program keypair
solana-keygen new -o target/deploy/covenant-mainnet.json
solana address -k target/deploy/covenant-mainnet.json     # → <MAINNET_PROGRAM_ID>

# 2. Put <MAINNET_PROGRAM_ID> in BOTH places:
#    - programs/covenant/src/lib.rs   →  declare_id!("<MAINNET_PROGRAM_ID>")
#    - Anchor.toml                     →  uncomment [programs.mainnet] and set it

# 3. Build (IDL is regenerated by CI's pinned toolchain; locally use --no-idl to
#    verify the program compiles — see memory: anchor build IDL-gen is toolchain
#    sensitive).
anchor build            # in CI / a toolchain that can build the IDL
# or, to just verify the program compiles locally:
anchor build --no-idl
```

Copy the regenerated IDL to the bundled copies so the app + SDK match the
deployed program:

```bash
cp target/idl/covenant.json app/lib/covenant-idl.json
cp target/idl/covenant.json sdk/idl/covenant.json
cp target/idl/covenant.json sdk/src/idl/covenant.json
```

## 2. Deploy the program

Fund the deployer with ~6 SOL (program deploy + rent). Deploy with a hardware
wallet or Squads signer — do not use a hot key for the upgrade authority.

```bash
export RPC="https://mainnet.helius-rpc.com/?api-key=<KEY>"

# Preflight (read-only go/no-go, no spend):
DEPLOYER_KEYPAIR="$(cat ~/.config/solana/mainnet-deployer.json)" \
NEXT_PUBLIC_RPC_URL_MAINNET="$RPC" \
  node app/scripts/preflight-mainnet.mjs

# Deploy:
solana program deploy \
  --url "$RPC" \
  --keypair ~/.config/solana/mainnet-deployer.json \
  --program-id target/deploy/covenant-mainnet.json \
  target/deploy/covenant.so

# (Optional but recommended) hand the upgrade authority to a Squads multisig:
solana program set-upgrade-authority <MAINNET_PROGRAM_ID> \
  --new-upgrade-authority <SQUADS_AUTHORITY> --url "$RPC"
```

## 3. Initialize the protocol config

`init_config` is gated on the program's **upgrade authority** (H-1 fix), so it
must be called by the deployer/authority. Set REAL arbitrators.

```bash
DEPLOYER_KEYPAIR="$(cat ~/.config/solana/mainnet-deployer.json)" \
NEXT_PUBLIC_PROGRAM_ID_DEVNET=<MAINNET_PROGRAM_ID> \
NEXT_PUBLIC_RPC_URL=$RPC \
ARBITRATOR_1=<pubkey> ARBITRATOR_2=<pubkey> ARBITRATOR_3=<pubkey> \
ARBITRATOR_THRESHOLD=2 \
MIN_CHALLENGE_PERIOD_SECONDS=86400 \
MAX_CHALLENGE_PERIOD_SECONDS=604800 \
MIN_BOND_BPS=500 MIN_BOND_ABSOLUTE_USDC=1 \
  node app/scripts/init-config.mjs
```

> The init script passes the program + ProgramData accounts required by the
> upgrade-authority gate automatically. The `DEPLOYER_KEYPAIR` MUST be the
> program's upgrade authority or the call fails.

---

## 4. Point the app at mainnet (env only)

Set these in the production (and a preview) environment. **No code change.**

| Variable | Value |
|---|---|
| `COVENANT_ENV` | `mainnet` |
| `NEXT_PUBLIC_COVENANT_ENV` | `mainnet` |
| `SETTLEMENT_MODE` | `onchain` |
| `NEXT_PUBLIC_PROGRAM_ID_MAINNET` | `<MAINNET_PROGRAM_ID>` |
| `NEXT_PUBLIC_RPC_URL_MAINNET` | `https://mainnet.helius-rpc.com/?api-key=<KEY>` |
| `HELIUS_RPC_URL` | mainnet Helius URL (server) |
| `NEXT_PUBLIC_USDC_MINT_MAINNET` | *(optional — defaults to canonical USDC)* |
| `COVENANT_ARBITRATORS` | the 3 real arbitrator pubkeys |
| `SESSION_SECRET` | >=16 random chars (activates auth) |
| `CRANK_KEYPAIR` | funded keypair for the finalize crank |

`lib/network.ts` auto-selects mainnet RPC / USDC / explorer from these. On
mainnet the **faucet is disabled** and the app fails loudly if the program ID
env is missing (never falls back to the devnet program).

---

## 5. Post-deploy verification

- [ ] `preflight-mainnet.mjs` reports the program as **deployed + executable**.
- [ ] App badge shows **Mainnet**; explorer links omit `?cluster=devnet`.
- [ ] Create a tiny real job (e.g. 0.1 USDC), accept, submit, finalize — confirm
      USDC actually moved on mainnet explorer.
- [ ] Raise + resolve a dispute end-to-end with the real 2-of-3 arbitrators.
- [ ] Wallet login works (session cookie issued); acting on another wallet 403s.
- [ ] Faucet returns 403.
- [ ] Monitoring/alerts wired (`ALERT_WEBHOOK_URL`, dispute-spike, crank-failure).

---

## 6. Rollback / incident

- The program is **upgradeable** (until you revoke authority) — a fixed build can
  be redeployed to the same program ID via `solana program deploy`.
- To pause the app without an on-chain change, unset `SETTLEMENT_MODE=onchain`
  (falls back to the simulated/devnet demo paths) or flip `COVENANT_ENV` back to
  `devnet`. The DB mirror is preserved.
- Escrow funds are always in per-job PDAs owned by the program; they are never in
  a shared hot wallet, so an app outage does not put locked funds at risk.

---

## Notes

- Devnet remains the default: with none of the mainnet env vars set, everything
  behaves exactly as today.
- `MIN_CHALLENGE_PERIOD_SECONDS` on mainnet should be generous (>= 24h) so posters
  have real time to review before auto-release.
- Keep the deployer/upgrade-authority key offline (hardware or Squads).
